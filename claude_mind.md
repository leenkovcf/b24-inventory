# Claude Mind — Складская аналитика Битрикс24

## Проект
- **Файл**: `d:/b24test/index.html` — единственный файл, статика на GitHub Pages
- **URL**: `https://leenkovcf.github.io/b24-inventory/`
- **GitHub**: `https://github.com/leenkovcf/b24-inventory.git` (ветка `main`)
- **Битрикс24**: ТеплЭко | РосКедр, on-premise v26.0.0
- **Вебхук**: хранится в `localStorage['inv_webhook_v1']`

## Архитектура
- Одностраничное SPA, без фреймворков, Chart.js для графиков
- Данные: `catalog.storeproduct.list` (склад), `catalog.product.list` (товары), `crm.deal.*` (продажи)
- Аутентификация: только вебхук Битрикс24
- Кэш продаж аналитики: `sessionStorage['inv_sales_v7']` (версию менять при изменении логики загрузки)
- Дефицит: независимые данные в `runoutData/runoutDays/runoutLoading`, не кэшируется, грузит ВСЕ сделки без лимита
- Настройки: `localStorage` (ниже список ключей)

| Метод | Назначение |

## CRM — важные детали
- **Воронка Маркетплейсы**: сделки НЕ списывают со склада → исключать через `inv_excl_cat_v1`
- **Поле магазина**: `UF_CRM_SHOP` (хранит ID магазина числом или "Калининград [30]")
- **PRODUCT_ID = 0**: товар добавлен вручную, не из каталога → матчинг по названию
- **select['UF_*']**: нужно передавать явно, `select['*']` UF-поля НЕ возвращает
- **28 603 сделок** за 90 дней = почти все маркетплейсы; реальные магазинные = ~21 000 после фильтра
- **Лимит загрузки**: MAX_DEALS = 5000 (самые свежие, ORDER BY CLOSEDATE DESC)
- **CLOSEDATE**: дата закрытия сделки (не создания) — по ней считаются продажи

## Структура salesData
```javascript
salesData = {
  [productId]: {
    [storeId]: количество,   // продажи в конкретном магазине
    '__ALL__': количество,   // когда UF_CRM_SHOP не заполнен
  }
}
```
`hasPerCity = true` если хоть один ключ ≠ `'__ALL__'` с qty > 0

## Матчинг товаров CRM → каталог
1. `PRODUCT_ID > 0` и есть в `stock` → прямой матч
2. Точное совпадение имени (lowercase)
3. `matchProductByWords(name, map)` — пересечение слов >3 букв (без стоп-слов), порог ≥ 0.35

Стоп-слова: `для в и на с к по от до из при о за под над без не или`

## resolveShop — матчинг поля магазина
1. Прямой числовой ID
2. Формат "Калининград [30]" → берёт ID из скобок
3. Точное совпадение названия
4. Нормализация по падежам: `normCity = w => w.toLowerCase().replace(/[аяеёуюиьъ]+$/,'')`
5. Префикс-матч

`cityName(title)` убирает "Магазин в/во " из начала названия склада.

## ABC-анализ
- A: топ 20% товаров по объёму продаж (ключевые позиции)
- B: следующие 60%
- C: нижние 20% (кандидаты на вывод)
- Показывает 5 позиций на класс, кнопка "Показать все (N)" раскрывает остальные

## Таблица "Скоро закончатся"
- Порог = `SALES_DAYS` (выбранный период)
- `days = floor(stock / (qty_sold / SALES_DAYS))`
- Если `hasPerCity=true` — точные данные по каждому складу
- Если `hasPerCity=false` — оценочно (пропорционально остаткам)
- Фильтр по городам через кнопки + `data-city` на строках
- `filterRunout(city, btn)` — глобальная функция фильтрации

## Параллельная загрузка (Promise.all)
```javascript
const CONCURRENCY = 5; // 5 батч-запросов параллельно
```
Пагинация сделок: батчи по 49 страниц → ~3 API-вызова для 5000 сделок
Строки товаров: батчи по 49 сделок × 5 параллельных = ~21 вызов для 5000

## Диагностика CRM
- Раздел "Управление" → "Профили" → "Диагностика данных CRM"
- Показывает: 5 последних сделок + UF-поля + воронки (если API работает)
- `crm.deal.category.list` может вернуть 404 (обрабатывается gracefully)
- Обязательно `select[1]:'UF_*'` для получения UF-полей

## UI структура
- 3 таба: Остатки / Аналитика / Управление
- Аналитика: период-бар (30/60/90д) → предупреждения → KPI → runout → графики → ABC + города
- Управление: товары / города / профили / фильтр воронок / диагностика
- Роли: `admin` (всё), `director` (всё без вебхука), `manager` (только свои города)

## Известные ограничения
- `crm.deal.category.list` → 404 на некоторых версиях/правах v26
- `PRODUCT_ID=0` у маркетплейсных товаров (длинные SEO-названия) → плохо матчатся
- UF_CRM_SHOP пустой у маркетплейсных сделок (у них свои поля UF_CRM_MPWAREHOUSE и т.д.)
- ClickHouse БД у клиента (таблицы crm_deal, crm_deal_product_row, crm_deal_uf) — не используется
